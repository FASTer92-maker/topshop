# User Stories

> Формат: «Как <роль>, я хочу <действие>, чтобы <ценность>».
> Приоритет по MoSCoW: **Must** (обязательно к сдаче), **Should** (желательно), **Could** (если останется время).
> Критерии приемки записаны в стиле *Дано / Когда / Тогда*. Каждая история связана с этапом из [IMPLEMENTATION_PLAN.md](IMPLEMENTATION_PLAN.md) и тестами, которые её проверяют.

## Покупатель и гость

### US-01. Регистрация
**Как** гость, **я хочу** зарегистрироваться по email и паролю, **чтобы** покупать товары и видеть свои заказы.

**Критерии приемки:**
1. **Дано** я не авторизован, **когда** я открываю `/registration/new`, **тогда** вижу форму с полями: Email, Имя, Фамилия, Пароль, Подтверждение пароля.
2. **Когда** я отправляю корректные данные, **тогда** создаётся пользователь с ролью `customer`, я сразу авторизован, меня перенаправляет на главную, и я вижу сообщение «Добро пожаловать!».
3. **Когда** email уже занят (регистр не важен, пробелы по краям отбрасываются), **тогда** форма показывается снова с ошибкой «Email уже используется».
4. **Когда** пароль короче 8 символов или не совпадает с подтверждением, **тогда** вижу ошибку валидации на русском, и пользователь не создаётся.
5. **Когда** я подставляю в запрос параметр `role=admin`, **тогда** он игнорируется, и роль остаётся `customer`.
6. **Дано** я уже авторизован, **когда** открываю страницу регистрации, **тогда** меня перенаправляет на главную.

**Тесты:** `UserTest` (валидации, нормализация email, роль по умолчанию), `RegistrationsControllerTest` (успех, ошибки, защита от `role`), system `RegistrationTest`.

### US-02. Вход, выход и сброс пароля
**Как** зарегистрированный пользователь, **я хочу** входить, выходить и восстанавливать пароль, **чтобы** иметь безопасный доступ к своему аккаунту.

**Критерии приемки:**
1. **Когда** я ввожу верные email и пароль на `/session/new`, **тогда** я авторизован и попадаю на страницу, которую пытался открыть, или на главную.
2. **Когда** данные неверные, **тогда** вижу «Неверный email или пароль», и сессия не создаётся.
3. **Когда** я нажимаю «Выйти», **тогда** сессия удаляется, и в шапке снова кнопки «Войти» и «Регистрация».
4. **Когда** я запрашиваю сброс пароля, **тогда** на email уходит письмо со ссылкой (в development видно в логе). По ссылке можно задать новый пароль.
5. **Когда** я авторизован, **тогда** в шапке видны моё имя, ссылки «Мои заказы» и «Выйти». У администратора дополнительно есть «Админ-панель».
6. Частые попытки входа ограничиваются (rate limit генератора).

**Тесты:** `SessionsControllerTest`, `PasswordsControllerTest`, system `SignInTest`.

### US-03. Главная страница
**Как** посетитель, **я хочу** видеть на главной категории и новинки, **чтобы** быстро начать выбор.

**Критерии приемки:**
1. **Когда** я открываю `/`, **тогда** вижу приветственный баннер, сетку категорий (название и количество активных товаров) и блок «Новинки» из 8 последних активных товаров.
2. Неактивные товары на главной не показываются.
3. Клик по категории открывает каталог, отфильтрованный по этой категории. Клик по товару открывает его страницу.
4. **Дано** товаров нет, **тогда** вместо блока «Новинки» показано пустое состояние «Скоро здесь появятся товары».

**Тесты:** `HomeControllerTest`, `ProductTest` (scope `active`, `newest`).

### US-04. Каталог по категориям с пагинацией
**Как** покупатель, **я хочу** просматривать товары по категориям постранично, **чтобы** удобно изучать ассортимент.

**Критерии приемки:**
1. **Когда** я открываю `/products`, **тогда** вижу карточки активных товаров (изображение или заглушка, название, цена в ₽, «В наличии» / «Нет в наличии»), по 12 на страницу.
2. Под сеткой есть навигация Pagy. Номер страницы хранится в URL (`?page=2`).
3. **Когда** я выбираю категорию в боковой панели (или открываю `/categories/:slug`), **тогда** вижу только товары этой категории, а категория выделена как активная.
4. **Когда** я перехожу на несуществующую категорию, **тогда** получаю 404.
5. Список строится без N+1 (`includes(:category)`, `with_attached_image`).

**Тесты:** `ProductsControllerTest`, `CategoriesControllerTest`, system `CatalogBrowsingTest`.

### US-05. Поиск товаров
**Как** покупатель, **я хочу** искать товар по слову, **чтобы** быстро найти нужное.

**Критерии приемки:**
1. В шапке на каждой странице есть строка поиска. **Когда** я ввожу запрос и нажимаю Enter, **тогда** попадаю в `/products?q=...`.
2. Поиск идёт по названию и описанию, регистр не важен (`ILIKE`). Спецсимволы `%` и `_` экранируются.
3. Найденные товары показываются с пагинацией. Над сеткой написано: «Найдено: N по запросу «…»».
4. **Когда** ничего не найдено, **тогда** вижу «По вашему запросу ничего не найдено» и ссылку «Сбросить поиск».
5. Поиск сочетается с фильтрами и категорией (US-06).

**Тесты:** `ProductTest` (scope `search`), `ProductsControllerTest`, system `SearchTest`.

### US-06. Фильтры и сортировка
**Как** покупатель, **я хочу** отфильтровать товары по цене и наличию и отсортировать их, **чтобы** сузить выбор.

**Критерии приемки:**
1. В боковой панели каталога есть поля «Цена от» и «Цена до», флажок «Только в наличии», выпадающий список сортировки: «Новинки», «Сначала дешёвые», «Сначала дорогие», «По названию».
2. **Когда** я применяю фильтры, **тогда** обновляется только область результатов (Turbo Frame `products`), URL меняется (`data-turbo-action="advance"`), и ссылку можно отправить другому человеку.
3. Некорректные значения (буквы, отрицательные числа) игнорируются и не приводят к ошибке 500.
4. Пагинация сохраняет текущие фильтры.
5. Кнопка «Сбросить» очищает все фильтры.

**Тесты:** `ProductTest` (scopes `in_category`, `price_from`, `price_to`, `in_stock`, `sorted_by`), `ProductsControllerTest`, system `FilterTest`.

### US-07. Страница товара
**Как** покупатель, **я хочу** видеть подробную информацию о товаре, **чтобы** принять решение о покупке.

**Критерии приемки:**
1. **Когда** я открываю `/products/:slug`, **тогда** вижу изображение, название, категорию (ссылкой), цену, артикул (SKU), остаток («В наличии: N шт.» / «Нет в наличии») и описание.
2. Есть поле количества (от 1 до `stock`) и кнопка «В корзину». Если товара нет в наличии, кнопка неактивна.
3. Гость вместо кнопки видит «Войдите, чтобы купить» со ссылкой на вход.
4. Неактивный или несуществующий товар даёт 404 (для покупателя).
5. Внизу блок «Другие товары категории» (до 4 штук).

**Тесты:** `ProductsControllerTest#show`, system `ProductPageTest`.

### US-08. Добавление товара в корзину
**Как** покупатель, **я хочу** добавлять товары в корзину, **чтобы** купить несколько товаров одним заказом.

**Критерии приемки:**
1. **Дано** я авторизован, **когда** нажимаю «В корзину» на карточке или странице товара, **тогда** товар добавляется. Счётчик в шапке обновляется без перезагрузки (Turbo Stream), и я вижу уведомление «Товар добавлен в корзину».
2. **Когда** товар уже в корзине, **тогда** количество увеличивается, и повторная строка не создаётся.
3. **Когда** итоговое количество превышает остаток, **тогда** товар не добавляется, и я вижу «Недостаточно товара на складе (доступно: N)».
4. Неактивный товар добавить нельзя.
5. **Дано** я гость, **когда** нажимаю «В корзину», **тогда** меня перенаправляет на страницу входа.

**Тесты:** `CartTest#add_product`, `CartItemTest` (валидации), `CartItemsControllerTest` (гость → редирект, Turbo Stream-ответ), system `AddToCartTest`.

### US-09. Управление корзиной
**Как** покупатель, **я хочу** менять количество и удалять товары в корзине, **чтобы** скорректировать заказ перед оформлением.

**Критерии приемки:**
1. **Когда** я открываю `/cart`, **тогда** вижу список позиций (изображение, название, цена за единицу, количество, сумма по позиции), общую сумму и кнопку «Оформить заказ».
2. **Когда** я меняю количество (кнопками «−» / «+» или полем), **тогда** пересчитываются сумма по позиции, общая сумма и счётчик в шапке, и страница не перезагружается (Turbo Stream).
3. Количество не может быть меньше 1 или больше остатка. При ошибке показывается сообщение, а значение не сохраняется.
4. **Когда** я нажимаю «Удалить», **тогда** строка исчезает без перезагрузки, и суммы пересчитываются.
5. **Когда** корзина пуста, **тогда** вижу «Ваша корзина пуста» и кнопку «Перейти в каталог». Кнопка оформления скрыта.
6. Если товар после добавления стал неактивным или его остатка не хватает, в корзине появляется предупреждение, и оформить заказ нельзя до исправления.
7. Я вижу и меняю только свою корзину. Попытка изменить чужой `cart_item` даёт 404.

**Тесты:** `CartTest` (`total`, `items_count`, `checkout_ready?`), `CartItemsControllerTest` (update / destroy, чужой item), system `CartManagementTest`.

### US-10. Оформление заказа
**Как** покупатель, **я хочу** оформить заказ из корзины, **чтобы** купить выбранные товары.

**Критерии приемки:**
1. **Дано** корзина не пуста, **когда** я нажимаю «Оформить заказ», **тогда** вижу форму: ФИО (заполнено из профиля), телефон, адрес, комментарий, а также сводку корзины и итог.
2. ФИО, телефон и адрес обязательны. Телефон проверяется по простому формату. Ошибки показываются у полей.
3. **Когда** я подтверждаю заказ, **тогда** в одной транзакции:
   - создаётся `Order` со статусом `pending`, уникальным номером (например, `ORD-20261108-4F2A`) и `total`;
   - для каждой позиции создаётся `OrderItem` с `product_name` и `unit_price`, **скопированными** из товара;
   - `stock` каждого товара уменьшается на купленное количество;
   - корзина очищается.
4. После успеха меня перенаправляет на страницу заказа с сообщением «Заказ № … оформлен».
5. **Когда** остатка какого-либо товара не хватает (например, его купил другой покупатель), **тогда** ничего не сохраняется (откат транзакции), остатки не меняются, и я возвращаюсь в корзину с сообщением, какого товара не хватает.
6. Если позже изменить цену товара в админке, цена в уже оформленном заказе не меняется.
7. С пустой корзиной оформить заказ нельзя: меня перенаправляет в корзину.

**Тесты:** `OrderTest.place_from_cart!` (успех, недостаток остатка → откат, снимок цены, очистка корзины, расчёт total), `OrderItemTest`, `OrdersControllerTest#create`, system `CheckoutTest` (полный путь от каталога до заказа).

### US-11. История заказов в личном кабинете
**Как** покупатель, **я хочу** видеть историю своих заказов, **чтобы** отслеживать их статус.

**Критерии приемки:**
1. **Когда** я открываю «Мои заказы» (`/orders`), **тогда** вижу таблицу своих заказов (номер, дата, количество товаров, сумма, статус цветным бейджем), новые сверху, с пагинацией.
2. **Когда** я открываю заказ, **тогда** вижу позиции с ценой на момент покупки, суммы, данные доставки и текущий статус.
3. Чужой заказ недоступен (404).
4. **Когда** заказов нет, **тогда** вижу «У вас пока нет заказов» и ссылку в каталог.
5. *(Could)* В статусе `pending` я могу отменить свой заказ. Остатки при этом возвращаются на склад.

**Тесты:** `OrdersControllerTest` (index / show, чужой заказ → 404), system `OrderHistoryTest`.

## Администратор

### US-12. Управление категориями
**Как** администратор, **я хочу** создавать, редактировать и удалять категории, **чтобы** структурировать каталог.

**Критерии приемки:**
1. В `/admin/categories` есть таблица категорий (название, slug, количество товаров) и кнопки «Создать», «Изменить», «Удалить».
2. Название обязательно и уникально (регистр не важен). Slug генерируется из названия транслитерацией, его можно отредактировать, он должен соответствовать `[a-z0-9-]` и быть уникальным.
3. Категорию с товарами удалить нельзя: появляется сообщение «Нельзя удалить категорию, в которой есть товары».
4. Удаление требует подтверждения (`data-turbo-confirm`).
5. Покупатель или гость на любом `/admin/*` получает редирект и сообщение «Доступ запрещён». Запрос не выполняется.

**Тесты:** `CategoryTest` (валидации, slug, `restrict_with_error`), `Admin::CategoriesControllerTest` (CRUD под admin, запрет для customer и гостя), system `AdminCategoriesTest`.

### US-13. Управление товарами
**Как** администратор, **я хочу** управлять товарами, **чтобы** поддерживать ассортимент, цены и остатки в актуальном состоянии.

**Критерии приемки:**
1. В `/admin/products` есть таблица (миниатюра, название, SKU, категория, цена, остаток, статус «Активен» / «Скрыт») с поиском по названию или SKU и пагинацией.
2. Форма товара содержит поля: категория (select), название, slug, SKU, описание, цена, остаток, «Активен», изображение (file field). Изображения принимаются только JPEG, PNG и WebP размером до 5 МБ.
3. Валидации: название, SKU, цена, остаток и категория обязательны; `price >= 0`; `stock` — целое `>= 0`; SKU и slug уникальны.
4. Ошибки валидации показываются в форме (ответ `422`, Turbo корректно перерисовывает форму).
5. Товар, который есть в заказах, удалить нельзя: вместо удаления его можно скрыть («Активен» = false). Скрытый товар исчезает с витрины, но остаётся в истории заказов.
6. Товар без заказов можно удалить (с подтверждением). Вместе с ним удаляются его позиции в корзинах.

**Тесты:** `ProductTest` (валидации, вложение, `restrict_with_error` для order_items), `Admin::ProductsControllerTest`, system `AdminProductsTest` (создание с загрузкой изображения).

### US-14. Управление заказами и статусами
**Как** администратор, **я хочу** видеть все заказы и менять их статус, **чтобы** обрабатывать покупки.

**Критерии приемки:**
1. В `/admin/orders` есть таблица всех заказов (номер, дата, покупатель, сумма, статус), фильтр-вкладки по статусу (Все / Новые / Оплачены / Отправлены / Доставлены / Отменены) и пагинация.
2. Карточка заказа содержит данные покупателя и доставки, позиции со снимками цен и итог.
3. Статус меняется только по допустимым переходам: `pending → paid → shipped → delivered`; `pending | paid → cancelled`. Кнопки показываются только для разрешённых переходов, а сервер дополнительно проверяет переход в модели.
4. Смена статуса обновляет бейдж и кнопки без перезагрузки (Turbo Stream).
5. **Когда** заказ отменяется, **тогда** в одной транзакции остатки всех его позиций возвращаются на склад (`stock += quantity`).
6. Недопустимый переход (например, `delivered → pending`) отклоняется с сообщением, и статус не меняется.

**Тесты:** `OrderTest` (`can_transition_to?`, `transition_to!`, `cancel!` с возвратом остатков), `Admin::OrdersControllerTest` (фильтр, смена статуса, запрет для customer), system `AdminOrdersTest`.

### US-15. Дашборд администратора *(Could)*
**Как** администратор, **я хочу** видеть сводку на главной странице админки, **чтобы** быстро оценить состояние магазина.

**Критерии приемки:**
1. На `/admin` есть карточки: количество заказов по статусам, выручка (сумма `total` без отменённых), количество товаров и категорий.
2. Есть список «Заканчиваются» с активными товарами, у которых `stock < 5`, и ссылками на редактирование.
3. Есть список последних 5 заказов.

**Тесты:** `Admin::DashboardControllerTest`, `OrderTest` (scope `revenue`), `ProductTest` (scope `low_stock`).
