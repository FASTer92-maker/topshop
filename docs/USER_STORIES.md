> Формат: «Как <роль>, я хочу <действие>, чтобы <ценность>».
> Приоритет по MoSCoW: **Must** (обязательно к сдаче), **Should** (желательно, принято командой в объём), **Could** (если останется время).

> Тексты интерфейса в кавычках взяты из дизайн-макета TopShop.

## Покупатель и гость

### US-01. Регистрация
**Как** гость, **я хочу** зарегистрироваться по email и паролю, **чтобы** покупать товары, сохранять избранное и видеть свои заказы.

**Критерии приемки:**
1. **Дано** я не авторизован, **когда** я открываю `/registration/new`, **тогда** вижу форму с полями: Email, Имя, Фамилия, Пароль, Подтверждение пароля.
2. **Когда** я отправляю корректные данные, **тогда** создаётся пользователь с ролью `customer`, я сразу авторизован, меня перенаправляет на главную, и я вижу «Добро пожаловать!».
3. **Когда** email уже занят (регистр не важен, пробелы по краям отбрасываются), **тогда** форма показывается снова с ошибкой «Email уже используется».
4. **Когда** пароль короче 8 символов или не совпадает с подтверждением, **тогда** вижу ошибку на русском, и пользователь не создаётся.
5. **Когда** я подставляю в запрос параметр `role=admin`, **тогда** он игнорируется, и роль остаётся `customer`.
6. **Дано** я уже авторизован, **когда** открываю страницу регистрации, **тогда** меня перенаправляет на главную.

**Тесты:** `UserTest` (валидации, нормализация email, роль по умолчанию), `RegistrationsControllerTest`, system `RegistrationTest`.

### US-02. Вход, выход и сброс пароля
**Как** зарегистрированный пользователь, **я хочу** входить, выходить и восстанавливать пароль, **чтобы** иметь безопасный доступ к аккаунту.

**Критерии приемки:**
1. **Когда** я ввожу верные email и пароль на `/session/new`, **тогда** я авторизован и попадаю на страницу, которую пытался открыть, или на главную.
2. **Когда** данные неверные, **тогда** вижу «Неверный email или пароль», и сессия не создаётся.
3. **Когда** я нажимаю «Выйти», **тогда** сессия удаляется, и в шапке снова «Войти».
4. **Когда** я запрашиваю сброс пароля, **тогда** на email уходит письмо со ссылкой (в development видно в логе). По ссылке можно задать новый пароль.
5. **Когда** я авторизован, **тогда** в шапке видны «Аккаунт» (имя), «Мои заказы» и «Выйти». У администратора дополнительно есть «Админ-панель».
6. Частые попытки входа ограничиваются (rate limit генератора).

**Тесты:** `SessionsControllerTest`, `PasswordsControllerTest`, system `SignInTest`.

### US-03. Главная страница
**Как** посетитель, **я хочу** сразу видеть разделы магазина и новинки, **чтобы** быстро начать выбор.

**Критерии приемки:**
1. **Когда** я открываю `/`, **тогда** вижу два крупных баннера «Мужское» и «Женское» (на телефоне друг под другом) с кнопкой «Смотреть», которая ведёт в каталог раздела.
2. Ниже идёт блок «Новинки»: 8 последних активных товаров в горизонтальной прокрутке. В карточке фото 3:4, название, цвета и цена.
3. Скрытые товары на главной не показываются. Товар, у которого нет вариантов в наличии, показывается с пометкой «Нет в наличии».
4. **Дано** товаров нет, **тогда** вместо новинок показано «Скоро здесь появятся товары».

**Тесты:** `HomeControllerTest`, `ProductTest` (scopes `active`, `newest`).

### US-04. Каталог по разделам и подкатегориям
**Как** покупатель, **я хочу** просматривать товары по разделам (Мужское, Женское, Аксессуары) и подкатегориям (Куртки, Брюки…), **чтобы** быстро найти нужный тип одежды.

**Критерии приемки:**
1. В шапке есть меню разделов: «Все · Мужское · Женское · Аксессуары». На телефоне оно прокручивается вбок.
2. **Когда** я открываю раздел (`/categories/muzhskoe`), **тогда** вижу товары **всех** его подкатегорий и список подкатегорий для уточнения.
3. **Когда** я открываю подкатегорию (`/categories/muzhskoe-kurtki`), **тогда** вижу только её товары. Хлебные крошки: «Главная › Мужское › Куртки».
4. Над сеткой выводится счётчик «N товаров» с правильной формой слова.
5. Товары выводятся по 12 на страницу с пагинацией Pagy, номер страницы в URL (`?page=2`).
6. Сетка: 4 колонки на десктопе, 2 на телефоне. Карточка: фото 3:4, название, цвета («Чёрный / Табачный»), цена; сердечко избранного (US-14).
7. Несуществующая категория даёт 404. Список строится без N+1.

**Тесты:** `CategoryTest#self_and_subcategory_ids`, `ProductTest#in_category`, `CategoriesControllerTest`, system `CatalogBrowsingTest`.

### US-05. Поиск товаров
**Как** покупатель, **я хочу** искать товар по слову, **чтобы** быстро найти нужное.

**Критерии приемки:**
1. В шапке на каждой странице есть «Поиск». Запрос открывает `/products?q=...`.
2. Поиск идёт по названию и описанию, регистр не важен (`ILIKE`). Спецсимволы `%` и `_` экранируются.
3. Результаты выводятся с пагинацией и счётчиком «N товаров».
4. **Когда** ничего не найдено, **тогда** вижу «Ничего не найдено. Измените фильтры.» и ссылку «Сбросить».
5. Поиск сочетается с разделом, подкатегорией и фильтрами (US-06).

**Тесты:** `ProductTest#search`, `ProductsControllerTest`, system `SearchTest`.

### US-06. Фильтры и сортировка
**Как** покупатель, **я хочу** отфильтровать товары по размеру, цвету, цене и наличию и отсортировать их, **чтобы** видеть только то, что мне подходит и есть в продаже.

**Критерии приемки:**
1. Над сеткой есть панель фильтров: «Категория» (подкатегории текущего раздела), «Размер» (Любой размер, XS … XXL, ONE SIZE), «Цвет», «Цена до … ₽», флажок «Только в наличии» и «Сортировка» (По умолчанию, Сначала дешёвые, Сначала дорогие).
2. Фильтр по размеру показывает только товары, у которых этот размер **есть в наличии** (`stock > 0`).
3. **Когда** я меняю фильтр, **тогда** обновляется только сетка (Turbo Frame `catalog`), URL меняется (`data-turbo-action="advance"`), и ссылкой можно поделиться.
4. Некорректные значения (буквы в цене, несуществующий размер) игнорируются и не приводят к ошибке 500.
5. Пагинация сохраняет фильтры. Кнопка «Сбросить» очищает их все.
6. Один товар не дублируется в выдаче, даже если подходят несколько его вариантов.

**Тесты:** `ProductTest` (`with_size`, `with_color`, `in_stock`, `price_to`, `sorted_by`, отсутствие дублей), `ProductsControllerTest`, system `FilterTest`.

### US-07. Страница товара
**Как** покупатель, **я хочу** видеть подробную информацию о товаре, **чтобы** принять решение о покупке.

**Критерии приемки:**
1. **Когда** я открываю `/products/:slug`, **тогда** вижу фото 3:4, название, раздел и подкатегорию (ссылками), цену и описание (состав, уход).
2. Есть выбор размера и цвета (US-08), кнопка «В корзину» и сердечко «В избранное».
3. Гость вместо «В корзину» видит «Войдите, чтобы купить».
4. Скрытый или несуществующий товар даёт 404.
5. Внизу блок «Похожие товары»: до 4 товаров той же подкатегории.

**Тесты:** `ProductsControllerTest#show`, system `ProductPageTest`.

### US-08. Выбор размера и цвета
**Как** покупатель, **я хочу** выбрать размер и цвет товара и видеть, что есть в наличии, **чтобы** купить подходящую мне вещь.

**Критерии приемки:**
1. На странице товара показаны цвета товара (кнопки с названием цвета) и размеры выбранного цвета в порядке XS → XXL.
2. Размеры, которых нет в наличии (`stock = 0`), видны, но неактивны (перечёркнуты), выбрать их нельзя.
3. При выборе размера под кнопкой показывается остаток, если он мал: «Осталось 2 шт.» (при `stock < 3`).
4. **Когда** я нажимаю «В корзину», не выбрав размер, **тогда** под размерами появляется красное «Выберите размер», и товар не добавляется. Это проверяется и на сервере: запрос без `variant_id` отклоняется.
5. **Дано** у товара единственный вариант (например, ONE SIZE), **тогда** он выбран автоматически.
6. **Дано** у товара нет вариантов в наличии, **тогда** вместо кнопки показано «Нет в наличии».
7. В корзину добавляется именно выбранный **вариант** (`variant_id`), а не товар.

**Тесты:** `VariantTest` (`available?`, порядок размеров, `label`), `ProductTest#available_sizes`, `CartItemsControllerTest` (без `variant_id` → ошибка), system `SizeSelectionTest` (без размера → «Выберите размер»; выбрать M → в корзине «M · Чёрный»).

### US-09. Добавление в корзину
**Как** покупатель, **я хочу** добавлять выбранный вариант товара в корзину, **чтобы** купить несколько вещей одним заказом.

**Критерии приемки:**
1. **Дано** я авторизован и выбрал размер, **когда** нажимаю «В корзину», **тогда** вариант добавляется, счётчик «Корзина (N)» в шапке обновляется без перезагрузки (Turbo Stream), и открывается корзина (переход на `/cart`).
2. **Когда** этот вариант уже в корзине, **тогда** увеличивается его количество. Тот же товар другого размера добавляется отдельной строкой.
3. **Когда** итоговое количество превышает остаток варианта, **тогда** вижу «Недостаточно товара на складе (доступно: N)», и количество не меняется.
4. Вариант скрытого товара добавить нельзя.
5. **Дано** я гость, **когда** нажимаю «В корзину», **тогда** меня перенаправляет на вход.

**Тесты:** `CartTest#add_variant`, `CartItemTest`, `CartItemsControllerTest`, system `AddToCartTest`.

### US-10. Управление корзиной
**Как** покупатель, **я хочу** видеть в корзине товары с размером и цветом, менять количество и удалять позиции, **чтобы** скорректировать заказ.

**Критерии приемки:**
1. **Когда** я открываю `/cart`, **тогда** вижу позиции: фото, название товара (ссылкой), **размер и цвет** («M · Чёрный»), цену за единицу, количество с кнопками «−» и «+», сумму по позиции. Справа итог (US-11) и «Оформить заказ».
2. **Когда** я нажимаю «−» или «+», **тогда** пересчитываются сумма по позиции, итог, доставка и счётчик в шапке без перезагрузки (Turbo Stream).
3. **Когда** количество уменьшается до нуля, **тогда** позиция удаляется. Количество не может превысить остаток варианта.
4. Есть кнопка «Удалить», она убирает строку без перезагрузки.
5. **Когда** корзина пуста, **тогда** вижу «Корзина пуста.» и ссылку в каталог. Кнопки оформления нет.
6. Если товар стал скрытым или остатка варианта не хватает, в строке появляется предупреждение, и оформление недоступно до исправления.
7. Я вижу и меняю только свою корзину. Чужой `cart_item` даёт 404.

**Тесты:** `CartTest` (`subtotal`, `items_count`, `checkout_ready?`, `unavailable_items`), `CartItemsControllerTest`, system `CartManagementTest`.

### US-11. Стоимость доставки
**Как** покупатель, **я хочу** заранее знать стоимость доставки и сколько осталось до бесплатной, **чтобы** решить, добавить ли ещё вещь.

**Критерии приемки:**
1. Доставка бесплатна, если сумма товаров **от 10 000 ₽ включительно**, иначе стоит **400 ₽**.
2. В корзине и при оформлении показываются строки «Товары», «Доставка» («Бесплатно» или «400 ₽») и «Итого».
3. **Когда** сумма меньше 10 000 ₽, **тогда** видна подсказка «До бесплатной доставки: N ₽». **Когда** порог достигнут, **тогда** видно «Доставка бесплатная».
4. Подсказка и итог обновляются вместе с изменением количества (Turbo Stream).
5. В заказе сохраняются `subtotal`, `delivery_price` и `total`. Если позже изменить тарифы, старые заказы не меняются.
6. Чёрная полоса в шапке на всех страницах: «Бесплатная доставка от 10 000 ₽».

**Тесты:** `DeliveryTest` (9 999 → 400, 10 000 → 0, 15 000 → 0; `amount_to_free`), `CartTest` (`delivery_price`, `amount_to_free_delivery`, `total`), system-проверка подсказки в `CartManagementTest`.

### US-12. Оформление заказа
**Как** покупатель, **я хочу** оформить заказ из корзины, **чтобы** купить выбранные вещи.

**Критерии приемки:**
1. **Дано** корзина не пуста, **когда** я нажимаю «Оформить заказ», **тогда** вижу форму (ФИО заполнено из профиля, телефон, адрес, комментарий) и состав заказа с размерами, доставкой и итогом.
2. ФИО, телефон и адрес обязательны. Ошибки показываются внутри формы, без перезагрузки остальной страницы (Turbo Frame `checkout`, ответ `422`).
3. **Когда** я подтверждаю заказ, **тогда** в одной транзакции:
   - создаётся `Order` со статусом «Новый», уникальным номером, `subtotal`, `delivery_price` и `total`;
   - для каждой позиции создаётся `OrderItem` со **снимком** названия, размера, цвета и цены;
   - остаток (`stock`) каждого **варианта** уменьшается на купленное количество;
   - корзина очищается.
4. После успеха показывается экран «Заказ принят» с номером и статусом «новый» и пометкой «Оплата имитируется, платёж не проводится».
5. **Когда** остатка какого-либо варианта не хватает (его купил другой покупатель), **тогда** ничего не сохраняется (откат транзакции), и я возвращаюсь в корзину с сообщением, какого товара и размера не хватает.
6. Изменение цены, названия или цвета в админке не меняет уже оформленные заказы.
7. С пустой корзиной оформить заказ нельзя: меня перенаправляет в корзину.

**Тесты:** `OrderTest.place_from_cart!` (успех, снимки, уменьшение остатков вариантов, доставка, откат при нехватке, пустая корзина), `OrdersControllerTest`, system `CheckoutTest` (путь от выбора размера до «Заказ принят»).

### US-13. История заказов в личном кабинете
**Как** покупатель, **я хочу** видеть историю своих заказов, **чтобы** отслеживать их статус.

**Критерии приемки:**
1. В «Мои заказы» (`/orders`) есть таблица: номер, дата, количество вещей, сумма, статус (бейдж). Новые сверху, с пагинацией.
2. В карточке заказа видны позиции с размером, цветом и ценой на момент покупки, а также товары, доставка, итог, данные доставки и шкала статусов «новый → оплачен → собран → отправлен → доставлен».
3. Чужой заказ недоступен (404).
4. **Когда** заказов нет, **тогда** вижу «У вас пока нет заказов» и ссылку в каталог.
5. *(Could)* Заказ в статусе «Новый» я могу отменить сам, остатки при этом возвращаются.

**Тесты:** `OrdersControllerTest` (index, show, чужой заказ → 404), system `OrderHistoryTest`.

### US-14. Избранное
**Как** покупатель, **я хочу** отмечать понравившиеся товары сердечком, **чтобы** вернуться к ним позже.

**Критерии приемки:**
1. На карточке товара (в каталоге и на главной) и на странице товара есть кнопка-сердечко ♡.
2. **Дано** я авторизован, **когда** нажимаю ♡, **тогда** товар добавляется в избранное, сердечко становится закрашенным, а счётчик ♡ в шапке увеличивается. Всё без перезагрузки (Turbo Stream). Повторное нажатие убирает товар из избранного.
3. В избранное добавляется товар целиком, без размера.
4. Страница `/favorites` (ссылка ♡ в шапке) показывает мои избранные товары той же сеткой карточек. Если их нет: «В избранном пока пусто».
5. Скрытые товары в избранном помечаются «Нет в продаже» и не ведут на страницу товара.
6. **Дано** я гость, **когда** нажимаю ♡, **тогда** меня перенаправляет на вход.
7. Повторное добавление не создаёт дубль (уникальный индекс `user_id + product_id`).

**Тесты:** `FavoriteTest` (уникальность), `UserTest#toggle_favorite!`, `FavoritesControllerTest` (гость → вход, toggle, Turbo Stream, только свои), system `FavoritesTest`.

### US-15. Подписка на рассылку
**Как** посетитель, **я хочу** подписаться на новости по email, **чтобы** узнавать о новинках и акциях.

**Критерии приемки:**
1. Над футером на всех страницах есть блок «Новости и акции»: «Подпишитесь на рассылку», поле email и кнопка «Подписаться».
2. **Когда** я ввожу корректный email, **тогда** внутри блока (Turbo Frame `newsletter`) появляется «Спасибо! Подписка оформлена.» без перезагрузки страницы.
3. **Когда** email уже подписан, **тогда** я вижу то же сообщение, и дубль не создаётся. Так нельзя выяснить, есть ли адрес в базе.
4. **Когда** email некорректный, **тогда** внутри блока видна ошибка, и запись не создаётся.
5. Подписка доступна гостю, авторизация не нужна. Частые запросы ограничиваются (rate limit).
6. Письма в рамках MVP не отправляются, адреса только сохраняются.

**Тесты:** `SubscriberTest` (нормализация, формат, уникальность, `subscribe`), `SubscribersControllerTest` (успех, дубль, ошибка, Turbo Frame), system `NewsletterTest`.

## Администратор

### US-16. Управление разделами и подкатегориями
**Как** администратор, **я хочу** управлять деревом категорий (разделы → подкатегории), **чтобы** структурировать каталог.

**Критерии приемки:**
1. В `/admin/categories` разделы показаны списком, их подкатегории — с отступом под ними. Видны название, slug, порядок и количество товаров.
2. Форма: название, родитель (select: «— Раздел верхнего уровня —» или один из разделов), slug, описание, порядок.
3. Название уникально внутри родителя: «Куртки» могут быть и в «Мужском», и в «Женском», а два раздела «Мужское» — нет. Slug генерируется автоматически (`muzhskoe-kurtki`) и глобально уникален.
4. Глубина не больше двух уровней: подкатегорию нельзя выбрать родителем.
5. Нельзя удалить раздел с подкатегориями и категорию с товарами. Показывается понятное сообщение.
6. Удаление требует подтверждения (`data-turbo-confirm`).
7. Покупатель или гость на любом `/admin/*` получает редирект и «Доступ запрещён».

**Тесты:** `CategoryTest` (дерево, глубина, уникальность в рамках родителя, slug, `restrict_with_error`), `Admin::CategoriesControllerTest`, system `AdminCategoriesTest`.

### US-17. Управление товарами
**Как** администратор, **я хочу** создавать и редактировать товары, **чтобы** поддерживать ассортимент и цены в актуальном состоянии.

**Критерии приемки:**
1. В `/admin/products` есть таблица: миниатюра, название, раздел › подкатегория, цена, число вариантов, суммарный остаток, статус «Активен» / «Скрыт». Есть поиск по названию или артикулу варианта и пагинация.
2. Форма товара: подкатегория (select с группами по разделам), название, slug, описание, цена, «Активен», изображение (JPEG, PNG, WebP до 5 МБ).
3. Валидации: название, цена и подкатегория обязательны; `price >= 0`; slug уникален; раздел верхнего уровня как категорию товара выбрать нельзя.
4. После создания товара меня перенаправляет на его страницу в админке, где добавляются варианты (US-18).
5. Товар, варианты которого есть в заказах, удалить нельзя, только скрыть. Товар без заказов удаляется вместе с вариантами (с подтверждением).

**Тесты:** `ProductTest` (валидации, подкатегория, изображение, запрет удаления с заказами), `Admin::ProductsControllerTest`, system `AdminProductsTest`.

### US-18. Управление вариантами: размеры, цвета, остатки
**Как** администратор, **я хочу** задавать товару варианты с размером, цветом, артикулом и остатком, **чтобы** покупатели видели актуальное наличие по размерам.

**Критерии приемки:**
1. На странице товара в админке есть таблица вариантов: размер, цвет, артикул, остаток и действия «Изменить» / «Удалить». Строки отсортированы по цвету и по размеру (XS → XXL).
2. Форма варианта: размер (select из `Variant::SIZES`), цвет, артикул (SKU), остаток.
3. Валидации: размер из списка; цвет обязателен; артикул уникален; остаток — целое `>= 0`; сочетание размер + цвет уникально для товара.
4. Добавление, изменение и удаление варианта обновляют таблицу без перезагрузки (Turbo Stream).
5. Вариант, который есть в заказах, удалить нельзя: появляется сообщение «Вариант есть в заказах — обнулите остаток».
6. Варианты с остатком меньше 3 подсвечены в таблице.

**Тесты:** `VariantTest` (валидации, уникальность, `restrict_with_error`), `Admin::VariantsControllerTest` (CRUD, доступ customer), system `AdminVariantsTest`.

### US-19. Управление заказами и статусами
**Как** администратор, **я хочу** видеть все заказы и менять их статус, **чтобы** обрабатывать покупки.

**Критерии приемки:**
1. В `/admin/orders` есть таблица всех заказов (номер, дата, покупатель, сумма, статус), вкладки-фильтры по статусу (Все / Новые / Оплачены / Собраны / Отправлены / Доставлены / Отменены) и пагинация.
2. В карточке заказа видны покупатель, доставка, позиции со снимками (название, размер, цвет, цена), а также товары, доставка и итог.
3. Статус меняется только по допустимым переходам: «новый → оплачен → собран → отправлен → доставлен». Отменить можно из статусов «новый», «оплачен» и «собран». Кнопки показываются только для разрешённых переходов, а сервер дополнительно проверяет переход в модели.
4. Смена статуса обновляет бейдж и кнопки без перезагрузки (Turbo Stream).
5. **Когда** заказ отменяется, **тогда** в одной транзакции остатки всех его **вариантов** возвращаются на склад.
6. Недопустимый переход отклоняется с сообщением, и статус не меняется.

**Тесты:** `OrderTest` (переходы, `cancel!` с возвратом остатков вариантов), `Admin::OrdersControllerTest`, system `AdminOrdersTest`.
