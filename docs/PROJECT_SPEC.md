# Спецификация проекта «Интернет-магазин»

> Рабочее название: **Top Shop**. Учебный командный проект на Ruby on Rails.
> Связанные документы: [USER_STORIES.md](USER_STORIES.md) · [ERD.md](ERD.md) · [WIREFRAMES.md](WIREFRAMES.md) · [IMPLEMENTATION_PLAN.md](IMPLEMENTATION_PLAN.md) · [CLAUDE.md](CLAUDE.md)

## 1. Назначение и цель

Top Shop — это веб-приложение розничного интернет-магазина. Покупатель находит товары в каталоге, кладёт их в корзину и оформляет заказ. Администратор ведёт ассортимент и обрабатывает заказы.

Цели проекта:

1. Сделать работающий MVP интернет-магазина на классическом монолите Rails 8.1: серверный рендеринг ERB, Hotwire, без SPA.
2. Показать грамотную работу с данными: миграции, связи, валидации, ограничения на уровне БД, транзакции.
3. Показать разграничение прав на сервере (две роли) и покрытие тестами (Unit + Feature/System).
4. Вести командную разработку через Git: feature-ветки, Pull Request'ы, логичные атомарные коммиты.

## 2. Целевая аудитория

| Аудитория | Что ей нужно |
|---|---|
| Покупатель (розничный клиент) | Быстро найти товар, узнать цену и наличие, оформить заказ, посмотреть историю заказов |
| Администратор магазина | Добавлять и редактировать товары и категории, следить за остатками, менять статусы заказов |
| Преподаватель / проверяющий | Проверить выполнение технических требований, запустить проект локально, пройти демо-сценарий |

## 3. Роли и права доступа

В системе две роли пользователя (`role` в таблице `users`): **customer** (по умолчанию) и **admin**. Гость — это неавторизованный посетитель, а не роль в БД.

Права проверяются **на сервере** (в `before_action` контроллеров и через ограничение выборок текущим пользователем). То, что кнопка скрыта в интерфейсе, защитой не считается.

| Действие | Гость | Customer | Admin |
|---|:---:|:---:|:---:|
| Главная, каталог, поиск, фильтры, страница товара | ✅ | ✅ | ✅ |
| Регистрация / вход | ✅ | — | — |
| Выход, сброс пароля | — / ✅ | ✅ | ✅ |
| Корзина: добавить, изменить количество, удалить | ❌ → редирект на вход | ✅ (только своя) | ✅ (только своя) |
| Оформление заказа | ❌ | ✅ | ✅ |
| Личный кабинет: свои заказы | ❌ | ✅ (только свои) | ✅ (только свои) |
| Админ-панель `/admin/*` | ❌ → вход | ❌ → редирект + сообщение «Доступ запрещён» | ✅ |
| CRUD категорий и товаров | ❌ | ❌ | ✅ |
| Просмотр всех заказов, смена статусов | ❌ | ❌ | ✅ |

> Чужой заказ ищется через `Current.user.orders.find(id)`, поэтому попытка открыть его даёт 404, а не данные другого пользователя.

## 4. Функциональный объём (MVP)

### 4.1. Витрина (публичная часть)
- **Главная страница**: баннер / приветствие, список категорий, блок «Новинки» (последние активные товары).
- **Каталог**: все активные товары с пагинацией (Pagy), фильтр по категории.
- **Поиск**: по названию и описанию товара (`ILIKE`, регистр не важен).
- **Фильтры и сортировка**: диапазон цены (от/до), «только в наличии»; сортировка: новинки, цена ↑, цена ↓, название А–Я.
- **Страница товара**: изображение, название, категория, цена, наличие, описание, кнопка «В корзину» с выбором количества.

### 4.2. Аутентификация
- Регистрация (email, имя, фамилия, пароль, подтверждение пароля).
- Вход / выход (сессии из генератора Rails 8 `bin/rails generate authentication`).
- Сброс пароля по email (из генератора; в development письма смотрим в логах).

### 4.3. Корзина (только для авторизованных)
- Одна корзина на пользователя, хранится в БД и доступна с любого устройства.
- Добавление товара. Если товар уже лежит в корзине, количество увеличивается.
- Изменение количества и удаление позиции без перезагрузки страницы (Turbo Streams).
- Нельзя положить больше, чем есть на складе (`stock`), и нельзя добавить неактивный товар.
- Счётчик товаров в шапке обновляется через Turbo Stream.

### 4.4. Оформление заказа
- Форма: ФИО получателя, телефон, адрес доставки, комментарий. ФИО заполняется из профиля.
- При подтверждении в **одной транзакции**:
  1. товары блокируются (`SELECT … FOR UPDATE`) и проверяются остатки;
  2. создаётся `Order` и позиции `OrderItem` со **снимком цены и названия** на момент покупки;
  3. `stock` каждого товара уменьшается;
  4. корзина очищается.
- Если хотя бы одного товара не хватает, транзакция откатывается и пользователь видит понятное сообщение.
- Страница подтверждения с номером заказа.

### 4.5. Личный кабинет
- История своих заказов: номер, дата, статус, сумма, с пагинацией.
- Детали заказа: позиции с ценой на момент покупки, адрес, статус.

### 4.6. Админ-панель (`/admin`)
- **Дашборд**: число заказов по статусам, выручка (без отменённых), товары с низким остатком.
- **Категории**: список, создание, редактирование, удаление (только если в категории нет товаров).
- **Товары**: список с поиском и пагинацией, создание и редактирование (включая загрузку изображения через Active Storage), деактивация. Товар, который уже есть в заказах, физически не удаляется.
- **Заказы**: список с фильтром по статусу и пагинацией, карточка заказа, смена статуса по допустимым переходам, отмена с возвратом остатков на склад.

### 4.7. Вне объёма MVP (явно не делаем)
- Онлайн-оплата, расчёт доставки, интеграции со службами доставки.
- Гостевая корзина (решение команды: корзина только после входа).
- Отзывы, рейтинги, избранное, промокоды, скидки.
- Варианты товаров (размер / цвет), несколько изображений у товара, ресайз изображений.
- Многоязычность (интерфейс только на русском, но через I18n).
- Деплой на сервер (сдача проходит локально: seeds + демо).
- JSON API, мобильное приложение.

## 5. Технологический стек

| Слой | Технология | Комментарий |
|---|---|---|
| Язык | Ruby 3.4.x | Установлен 3.4.1 |
| Фреймворк | **Ruby on Rails 8.1** (последняя стабильная 8.1.x) | Классический full-stack, **не** API-mode |
| БД | **PostgreSQL** (локально 18) | Внешние ключи, check constraints, `ILIKE` |
| ORM | ActiveRecord | Миграции, связи, валидации, scopes, транзакции |
| Представления | **ERB** + partials + хелперы | Без React / Vue |
| Стили | **Tailwind CSS** (`tailwindcss-rails`) | Standalone-бинарник, Node.js не нужен |
| JS / интерактивность | **Hotwire: Turbo** (+ Stimulus при необходимости), importmap | Turbo Frames и Turbo Streams |
| Аутентификация | **Генератор Rails 8** (`has_secure_password`, `bcrypt`) | Без Devise |
| Авторизация | Собственная: enum `role` + `before_action` | Без Pundit / CanCanCan |
| Пагинация | **Pagy** (актуальная стабильная версия) | Единственный «внешний» гем функциональности |
| Файлы | Active Storage, сервис `local` (Disk) | Без вариантов изображений, без libvips |
| Тесты | **Minitest**: модели, контроллеры (integration), system (Capybara + Selenium, headless Chrome) | Fixtures |
| Качество кода | RuboCop (`rubocop-rails-omakase`), Brakeman | Идут в комплекте с Rails 8 |
| Локализация | I18n, `config/locales/ru.yml`, `default_locale = :ru`, валюта ₽ | |
| VCS | Git + GitHub (feature-ветки + PR) | |

**Запрещено:** React и другие SPA-фреймворки, API-only режим, микросервисы, Devise и Pundit, а также любые гемы сверх перечисленных без согласования команды.

## 6. Нефункциональные требования

### 6.1. Безопасность
- Права проверяются только на сервере: `Admin::BaseController#require_admin`, `require_authentication` из генератора.
- Strong parameters во всех формах. Поле `role` **никогда** не входит в разрешённые параметры регистрации.
- CSRF-защита Rails включена. Пароли хранятся только в виде `password_digest` (bcrypt).
- Rate limit на вход (из генератора) и на регистрацию.
- Ресурсы пользователя выбираются в его скоупе (`Current.user.orders`, `Current.user.cart`).
- Перед сдачей Brakeman не должен выдавать предупреждений высокого уровня.

### 6.2. Целостность данных
- Внешние ключи (`foreign_key: true`) и `NOT NULL` там, где поле обязательно.
- Check constraints: `price >= 0`, `stock >= 0`, `quantity > 0`, `total >= 0`.
- Уникальные индексы: email, slug, sku, номер заказа, пара `(cart_id, product_id)`.
- Деньги хранятся в `decimal(10,2)`, никогда не в `float`.
- Оформление и отмена заказа выполняются атомарно (`transaction` + `lock!`).

### 6.3. Удобство и интерфейс
- Адаптивная вёрстка (mobile-first, Tailwind).
- Понятные flash-сообщения и ошибки валидации на русском.
- Пустые состояния: пустая корзина, нет заказов, ничего не найдено.
- Действия с корзиной и смена статуса заказа выполняются без полной перезагрузки страницы.

### 6.4. Производительность (в разумных пределах учебного проекта)
- Нет N+1 запросов на списках (`includes` / `with_attached_image`).
- Индексы под фильтры и сортировку каталога.
- Пагинация на всех списках, которые могут расти.

### 6.5. Качество и тестирование
- На каждый этап пишутся тесты. Этап не считается законченным, пока `bin/rails test` и `bin/rails test:system` не зелёные.
- Unit-тесты моделей: валидации, scopes, бизнес-методы (`Cart#add_product`, `Order.place_from_cart!`, `Order#cancel!`).
- Integration-тесты контроллеров: доступ по ролям, редиректы, ответы.
- System-тесты ключевых сценариев: регистрация, покупка от каталога до заказа, работа админа.

## 7. Глоссарий

| Термин | Значение | В коде |
|---|---|---|
| Каталог | Список активных товаров с поиском, фильтрами и пагинацией | `ProductsController#index` |
| Категория | Группа товаров (плоская, без вложенности) | `Category` |
| Товар | Единица ассортимента с ценой и остатком | `Product` |
| Остаток | Количество товара на складе | `products.stock` |
| Активный товар | Товар, который показывается на витрине и доступен к покупке | `products.active` |
| Корзина | Набор товаров пользователя перед оформлением | `Cart`, `CartItem` |
| Заказ | Оформленная покупка с адресом и статусом | `Order` |
| Позиция заказа | Товар в заказе с ценой на момент покупки | `OrderItem` |
| Снимок цены | Цена и название товара, скопированные в позицию заказа | `order_items.unit_price`, `product_name` |
| Статус заказа | `pending` (новый), `paid` (оплачен), `shipped` (отправлен), `delivered` (доставлен), `cancelled` (отменён) | `Order.statuses` |
